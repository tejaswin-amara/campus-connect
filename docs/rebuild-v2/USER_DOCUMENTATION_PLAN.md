# User and Administrator Documentation Plan

J17 produces release-matched documentation after actual workflows are stable. Do not write final instructions based on mockups or planned features.

## Student guide
Account/login; browse/search/filter; event details and eligibility; register/cancel; waitlist; tickets/QR; calendar; notifications/preferences; privacy and account support; troubleshooting.

## Club/department organizer guide
Organization membership/roles; create/edit/submit event; approval feedback; schedule/venue/capacity; roster and export policy; waitlist; cancellation/reschedule; assign check-in operators; event analytics.

## Event operator guide
Authorized sign-in; assigned event selection; attendee lookup; QR scanning; duplicate/invalid ticket handling; offline/degraded procedure if supported; correction escalation; privacy rules.

## College administrator guide
Organization approval; user/role administration; event moderation; categories/venues; ingestion source registration; sync failure and duplicate review; audit; exports; suspension/incident workflows.

## Developer/operator guide
Local setup; environment config; architecture; database/migrations; API reference; tests; CI/CD; deployment; monitoring; secrets; backups/restore; incident response; rollback; dependency updates; Jules task workflow.

## Documentation quality
Every procedure must identify role/prerequisite, exact steps, expected result, failure handling, screenshots only from approved synthetic/demo data, last verified release and owner.
